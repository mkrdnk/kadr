# Desktop: ручное HTTP-воспроизведение

Это первый интегрированный сценарий P1/P2, а не приёмка всех требований v1.0.
Каталог, реальный поиск источников, торрент-сессии UI и список библиотеки
ещё не подключены. Экраны показывают это явно, без демонстрационных результатов.

## Использование

1. Установите отдельно mpv или VLC. Бинарник ищется через `PATH`; отсутствие
   или неготовность IPC показываются как ошибка, приложение не падает.
2. Запустите `cargo run --locked -p kadr-app` в графической сессии.
3. В «Настройках» выберите плеер. Выбор подтверждается только после записи
   SQLite, действует при следующем запуске плеера и переживает перезапуск kadr.
4. Скопируйте HTTP(S)-ссылку на собственное или разрешённое видео.
   В «Источниках» нажмите «Вставить ссылку». Буфер не читается автоматически.
   Отображается тип источника, но не приватный URL/токен.
5. Для mpv «Продолжить / смотреть» восстанавливает ранее измеренную позицию,
   если она есть; «С начала» её не использует. После запуска kadr опрашивает
   реальный JSON IPC примерно раз в секунду, не подменяя позицию таймером.
6. «Остановить», закрытие окна или выход из kadr останавливают принадлежащий
   приложению плеер. Закрытие самого плеера также обнаруживается.

Громкость, дорожки и субтитры выбираются во внешнем плеере. Сворачивание kadr
**не** останавливает его worker или плеер; используйте «Остановить» либо выход.
Переключение настройки плеера не перезапускает активную сессию.

HTTP отдаётся напрямую внешнему плееру, без собственного remote proxy.
Контейнер/кодеки, redirects и поддержка HTTP seek зависят от источника/плеера.
Один лишь успешный запуск процесса не подтверждает первый декодированный кадр.
При потере IPC медиасессия останавливается; последняя успешно записанная
позиция остаётся в БД.

## Что сохраняется

SQLite хранит выбор плеера, историю успешных запусков и измеренный прогресс.
Для ручного источника ключом служит versioned SHA-256 от нормализованного
источника; credentials отвергаются, HTTP fragment не участвует в ключе.
Полный URL, session token и персональный путь в БД не сохраняются.
Поэтому для продолжения пока требуется снова вставить ту же ссылку.
Изменение подписанного query URL даёт новый ID — объединения таких источников
до интеграции каталога нет. Список библиотеки UI пока показывает только счётчик.

VLC 3 RC не предоставляет используемому прототипу надёжную корреляцию
телеметрии. Он открывается/останавливается управляемо, но новая позиция
**не записывается**; это явно отражено в статусе. Если для того же источника
есть позиция mpv, CLI resume VLC может её использовать, но это не обещание
дальнейшего отслеживания VLC.

Браузер пока не открывается: требование локального HTTP-потока и его lifecycle
не подменяются открытием произвольного remote URL. Предупреждение о контейнерах,
кодеках и недоступной телеметрии уже есть. Magnet и `.torrent` проверяются
лексически, без запуска сети; их метаданные/выбор файлов UI — следующий этап.

## Потоки и завершение

- `kadr-ui` хранит только presentation state и отправляет события.
- Контроллер `kadr-app` проверяет ввод, связывает UI с worker и отбрасывает
  устаревшие результаты диалога выбора по generation.
- Отдельный принадлежащий приложению поток владеет SQLite и Tokio runtime.
  Сетевые/player операции и синхронный SQL не выполняются в GPUI render loop.
- Очередь команд ограничена; запуск можно отменить отдельным токеном даже
  во время установления IPC. Launch future дожидается отмены и reaping,
  а не теряется при выходе из внешнего `select!`.
- GPUI даёт quit-observer только 100 мс. Он немедленно отменяет worker;
  после возврата platform event loop `main` дожидается остановки плеера и
  завершения worker. UI-thread не блокируется во время работы окна.

## Проверки

```sh
cargo test --locked --workspace
cargo test --locked -p kadr-media --test players_smoke -- --ignored --nocapture
cargo test --locked -p kadr-media --test video_smoke -- --ignored --nocapture
cargo test --locked -p kadr-app backend::tests::real_http_mpv_resume -- --ignored --nocapture
```

Обычные тесты проверяют приватность IPC, корректность сообщений, отмену,
timeout, process reaping, настройки и отказ storage. Opt-in smoke использует
собственный PCM WAV через существующий bearer HTTP-сервер. Сценарий worker
подтверждает реальное mpv-измерение → SQLite → новый worker → resume → явный
restart с начала → завершение при активном плеере. Это не тест декодирования
видео, GUI внешнего плеера или macOS. Отдельный opt-in `video_smoke` генерирует
собственное MPEG4/AAC MP4 средствами FFmpeg и подтверждает headless HTTP-
воспроизведение в обоих плеерах; визуальные кадры и A/V sync он не проверяет.

Сетевые/cache настройки пока являются сохранённой конфигурацией, не
реализованным enforcement. Desktop торрент-сеть не запускает, временный
видеокэш не создаёт. Не следует считать provisional 10 GiB в defaults
действующим ограничением диска. Release-приёмка требует подключения и
проверки cache manager и torrent lifecycle.
