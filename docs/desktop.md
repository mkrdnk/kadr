# Desktop: UI и медиаядро

`kadr-app` связывает GPUI с одним фоновым медиаядром. Экран не открывает SQLite,
не читает `.torrent`, не обращается к каталогу, не запускает плеер и не копирует
видео самостоятельно. Единственные нативные операции контроллера — чтение
буфера по нажатию и диалоги выбора файла, каталога и места сохранения.

## Архитектурная граница

Приложение разделено на два слоя, работающих в одном процессе:

```text
kadr-app (desktop adapter) + kadr-ui (GPUI presentation)
              Command ↓       ↑ Event
                 kadr-engine
                      │
         core / storage / media / torrent / catalog / cache
```

- `kadr-engine` — самостоятельная библиотека без GPUI. Она владеет worker,
  каталогом, источниками, торрентами, streaming, плеерами, SQLite и кэшем.
  Нижележащие `kadr-core`, `kadr-storage`, `kadr-media`, `kadr-torrent`,
  `kadr-catalog` и `kadr-cache` остаются её реализацией.
- `kadr-app` — клиент API движка. `desktop.rs` переводит `UiEvent` в `Command`
  и `Event` в экранные обновления. `desktop_models.rs` отвечает только за
  преобразование публичных данных движка в presentation DTO.
- `kadr-ui` содержит экранные модели, ввод, формы, навигацию и рендеринг.
  Его `UiEvent` не является API движка: выбор файла или вставка ссылки —
  действия desktop-интерфейса, а не медиаядра.

`Engine::start()` возвращает handle и поток `Event`. Для независимого клиента
или изолированных тестов `Engine::start_with_directories(EngineDirectories)`
принимает собственные каталоги данных, настроек и кэша. Клиент отправляет
`Command` через `dispatch`; успешная постановка команды в очередь не означает
успех операции. Результат подтверждается событием. `cancel()` начинает
завершение, `join()` отменяет работу и дожидается освобождения ресурсов.
Блокирующий `join()` нельзя вызывать в UI event loop.

Публичные `Settings`, `CacheUsage`, `LibraryItem` и `SourceCandidate` принадлежат
движку, а не SQLite/кэшу или GPUI. Строка библиотеки передаёт непрозрачный `id`:
UI возвращает его в `OpenLibrary`, не собирая из внутренних ключей БД.
В события источников и библиотеки не входят приватные URL, сохранённые
дескрипторы источников или пути торрентов. Общие provider-neutral модели
метаданных и валидируемого ручного ввода переиспользуются из `kadr-core`
через `kadr_engine::catalog` и `kadr_engine::source`.

Загрузчик постеров остаётся инфраструктурой интерфейса: он реализует GPUI
HTTP client. Его локальная политика по умолчанию выключена; desktop применяет
подтверждённый `catalog_enabled` из событий движка до обновления экрана.
Выход или закрытие event stream отключает постеры и отменяет текущие запросы.
Движок не обращается к HTTP client интерфейса и не знает про `--smoke-ui`.

Чтобы заменить UI, достаточно нового клиента команд/событий и своего
presentation adapter. Чтобы изменить storage, каталог или playback,
нужно сохранить семантику публичного API либо явно обновить его клиентов.
Новый транспорт, сериализация, локализация статусов и несколько одновременных
клиентов не входят в этот контракт: отдельный процесс/IPC здесь не вводится.

Направление зависимостей проверяет `scripts/check-architecture.py`:
desktop не может обходить engine и обращаться к нижним workspace-crates;
UI не импортирует engine; engine и его workspace-зависимости не импортируют
GPUI или presentation-crates.

## Запуск

1. Установите отдельно mpv или VLC и запустите
   `cargo run --locked -p kadr-app` в графической сессии.
2. В «Настройках» выберите плеер. Выбор подтверждается только событием об
   успешной записи настроек и действует при следующем запуске плеера.
3. Для сетевого каталога нужен настроенный Client ID приложения Trakt
   и включённый «Внешний каталог». В готовой сборке ID задаёт разработчик;
   при разработке используйте `KADR_TRAKT_CLIENT_ID`. Поиск отправляет введённое
   название в Trakt; ручные источники и сохранённая библиотека работают без ID.
4. Для BitTorrent отдельно разрешите торрент-сеть и задайте лимиты. BitTorrent
   может отдавать загруженные части другим участникам. Используйте только
   собственный контент или контент с разрешением на просмотр и распространение.

Отсутствующий плеер, недоступный каталог, ошибка источника и пустая выдача —
разные состояния. Ошибки не заменяются демонстрационными результатами или
нулевыми значениями телеметрии.

## Основные сценарии

### Найти фильм или серию

На главной можно загрузить полки каталога. Нажмите `Ctrl+K` / `⌘K`, введите
название и нажмите Enter либо откройте карточку с полки. Для сериала сначала
выберите эпизод. Метаданные Trakt не содержат воспроизводимого источника.
В карточке фильма **«Смотреть»** запускает явно выбранный источник. Если выбора
нет, kadr дожидается ответов включённых поставщиков (или их таймаутов) и запускает
подходящую раздачу с наибольшим известным числом сидов. Просто открыть карточку
недостаточно; если уйти во время поиска, плеер не откроется. Когда сидов нет
или их число неизвестно у всех подходящих раздач, откроются **«Источники»**.
То же окно можно открыть самому: раздачи фильма идут по убыванию сидов,
рекомендуемая отмечена. Выберите другую строку, дождитесь проверки, затем
нажмите «Смотреть». Если в торренте несколько видеофайлов и нужный не определён,
kadr предложит выбрать файл, а не запустит произвольный.

Окно «Источники» показывает привязанный ручной источник и результаты включённых
поставщиков по мере поступления. Wikimedia Commons предлагает только проверенные
открытые фильмы и показывает условия использования. Для RuTracker и Torznab
совпадение раздачи не подтверждает права на контент.
Атрибуция карточки включает лицензию и публичную страницу метаданных; приватный
адрес видео в модель экрана не передаётся.

Выбор строки передаёт worker-у идентификатор источника, а не позицию в списке. Только ответ медиаядра
разрешает воспроизведение; само наличие результата поиска этого не делает.

Если включены каталог и BitTorrent, тот же запрос показывает предложения
RuTracker с доступными качеством, размером и сидами. Выбор сначала проверяет
magnet темы, а при его отсутствии скачивает настоящий `.torrent`. Если ещё
нет действующей сессии, приложение использует пароль из системного хранилища
или показывает форму входа; браузер и сервер kadr не участвуют. В результатах
RuTracker права не проверены, а совпадение заголовка не заменяет проверку
раздачи и выбранного файла. Кнопка в «Настройках» удаляет сохранённый вход.

### Открыть свой источник

Скопируйте HTTP(S)- или magnet-ссылку и нажмите «Вставить ссылку» в «Источниках».
Либо выберите `.torrent` в нативном диалоге. Полный URL и параметры авторизации
не показываются. Содержимое `.torrent` читает только worker.

После получения метаданных выберите видеофайл. Для неоднозначного имени серии
можно явно назначить сезон и номер эпизода. Связь с карточкой каталога можно
снять отдельным действием; выбранный источник остаётся ручным.

Старый диалог `.torrent` не может заменить более новый источник: результаты
и ошибки проверяются по generation. Новый источник, выбор произведения или
эпизода, запуск, остановка и отмена делают прежние результаты недействительными.
Отмена самого диалога не стирает текущий источник. Неверная вставленная ссылка,
наоборот, отключает запуск старого источника, чтобы не воспроизвести его случайно.

### Смотреть, остановить, открыть другим плеером

«Продолжить / смотреть» запрашивает восстановление измеренной позиции.
«С начала» отправляет явный запуск без resume. «Открыть в…» переключает плеер
активной сессии, не меняя сохранённую настройку по умолчанию.

Контроллер отмечает запуск активным **до** отправки команды: повторный Play
и смена источника блокируются, а «Стоп» доступен уже во время запуска.
Остановка и отмена обращаются к cancellation tokens медиаядра, поэтому не
должны ждать завершения сетевых метаданных или установления IPC.

Громкость, дорожки и субтитры выбираются во внешнем плеере. Сворачивание kadr
не останавливает сессию. Выход останавливает принадлежащие приложению процессы.
Браузер открывает локальный поток, но поддержка контейнеров и кодеков ограничена;
автоматический прогресс произвольного браузера не обещается. Отображаемая позиция
mpv/VLC зависит от реальной доступной телеметрии, а не от времени после Play.

### Библиотека и избранное

Избранное, история и прогресс приходят из SQLite в виде отдельных строк.
Ключ строки — media ID, а не индекс, заголовок или адрес источника. Строка
содержит доступную позицию и длительность, а для серии — конкретный эпизод.
Открытие записи поручает worker-у восстановление сохранённого источника.
Если он недоступен, ошибка не удаляет саму запись истории.

Изменение избранного отображается после подтверждения медиаядра. Очистка
истории отправляет отдельную команду; контроллер не удаляет строки оптимистично.

### Сохранить и управлять кэшем

«Сохранить» открывает нативный save dialog в домашнем каталоге с последним
безопасным предложенным именем видео. Ни URL, ни приватный путь торрента не
используется как имя. Место выбирает пользователь; проверку назначения и
фактическую запись выполняет worker. Результат диалога для уже заменённого
источника отбрасывается. Состояние сохранения видно в «Передачах».

В настройках можно изменить лимит кэша и сетевые ограничения, включить каталог
или BitTorrent, выбрать каталог кэша и очистить неактивные временные данные.
Выбор нового каталога — запрос сохранения настроек, а не немедленная смена
показанного пути. Приложение подтверждает путь после успешной записи.
Очистка кэша не является удалением постоянного сохранённого файла.

`Paused`, конкретная скорость в байтах/с и `Unlimited` передаются без взаимных
подмен. Слишком большое число соединений отвергается до преобразования `u32`
в `u16`; окончательная проверка допустимых настроек выполняется медиаядром.
Подтверждение настроек заменяет редактируемый черновик значениями из SQLite.

## Потоки, события и завершение

- `kadr-ui` владеет только отображаемыми DTO и испускает `UiEvent`.
- `desktop.rs` преобразует события в `kadr_engine::Command`, а ответы
  `kadr_engine::Event` — в setters экрана.
  Источник, торрент-сессия и плеер не дублируются в контроллере.
- `SearchState` и `SourcesState` различают loading, ready (включая пустой
  результат) и error. Успех снимает прежнюю ошибку или индикатор загрузки.
- `PreferencesSaved` — единственное подтверждение записи настроек; enqueue
  команды им не считается. Последовательные изменения используют последний
  запрошенный набор, не теряя предыдущее ещё неподтверждённое изменение.
- `Transfer` сохраняет неизвестные скорости, пиры и размеры как `None`;
  отсутствие показателя не выдаётся за измеренный ноль.
- Закрытие event stream навсегда снимает readiness и доступность Play, очищает
  активный индикатор и аннулирует ожидающие диалоги. Нужен перезапуск приложения.
- Quit-observer немедленно отменяет worker, не блокируя GPUI. После завершения
  platform event loop `Desktop::join` дожидается его остановки вне quit-бюджета.

## Проверки

```sh
python3 scripts/check-architecture-test.py
python3 scripts/check-architecture.py
cargo test --locked -p kadr-engine
cargo test --locked -p kadr-app desktop::
cargo test --locked --workspace
cargo test --locked -p kadr-engine tests::real_ -- --ignored --test-threads=1
cargo test --locked -p kadr-media --test players_smoke -- --ignored --nocapture
cargo test --locked -p kadr-media --test video_smoke -- --ignored --nocapture
```

Тесты desktop проверяют преобразование настроек, отказ от переполнения peers,
приватность предложенного имени, неизвестную телеметрию и устаревшие generation.
Они не подтверждают работу нативных диалогов конкретного desktop окружения,
визуальное декодирование видео, A/V sync или macOS. Для этого нужны отдельные
ручные проверки в целевой графической сессии. Smoke-тесты плееров используют
собственные медиафайлы; запуск процесса не является доказательством первого кадра.
